# ATM 现金清分与钞箱交接平台

银行网点 **ATM 现金清分、钞箱交接、双人复核与差额管控** 的一体化演示平台。
账户、金额、卡号等全部为**虚构演示数据**。零外部运行依赖,仅需 Node.js ≥ 22(使用内置 `node:sqlite`)。

## 单条本地启动命令

```bash
npm start          # 等价:node src/server.js
```

启动时会**自动完成数据库迁移**,并在库为空时**自动写入样例**:
装钞计划(锁定→执行)、清机单(短款修正→平账→双人复核→关闭)、长款待复核单、
钞箱双人交接、离线暂存/上线补传、重复回传判重,以及演示账户/卡号/交易。

- 打开 http://localhost:3000 (端口可用 `PORT=4000 npm start` 覆盖)
- 数据库:`data/atm.db`(SQLite),清机附件:`data/attachments/`
- 首次启动即种子;删除 `data/` 后重启可重新生成演示数据

运行测试:

```bash
npm test
```

## 六个交付界面

顶部可切换**当前操作人**与**网点视角**(网点权限即时生效)。

| 标签 | 内容 |
|---|---|
| **ATM 台账** | 按网点分组卡片,展示 ATM 状态、在机钞箱、券别、张数、封签;可置离线/恢复在线 |
| **装钞计划** | 新建草稿→**锁定冻结**→执行装钞;明细含钞箱、券别、张数、右对齐金额、封签号 |
| **清机录入** | **按实点金额逐券别录入**、残钞张数,实时合计;自动核对短/长款;双人复核签名、关闭、金额修正、清机附件 |
| **钞箱轨迹** | 钞箱列表 + **封签状态连续轨迹时间线**;封存/开封/封签破损、领取(互斥)、离行双人签收 |
| **差额复核** | 短款/长款/残钞/封签破损/ATM 离线/重复回传六类卡片,**金额与处理期限同时高亮**,可处置 |
| **审计查询** | 全操作留痕检索、进程内补传队列状态、手动补传/模拟回传、演示账户/卡号/交易 |

## 核心业务规则(均有测试与接口约束)

- **计划锁定**:装钞前必须锁定;锁定后明细冻结,草稿不可执行装钞。
- **逐券别清机**:按券别录入实点张数与残钞张数,自动重算合计;短款(负)/长款(正)/残钞自动生成差额。
- **封签管控**:已封存钞箱**不能直接改数量**,须授权开封;执行装钞时系统开封→装入→重新封存并全程留痕;可登记封签破损。
- **双人复核**:清机单须**两名不同员工**签名,同一人不可重复;**复核完成前禁止关闭**;存在未处置差额同样禁止关闭。
- **金额修正留痕**:强制保留**原值、新值、原因、审批人**,经办人与审批人不得为同一人;修正后自动重算短/长款。
- **钞箱交接**:钞箱离开网点前必须封存,由**两名不同员工签收**,第二签完成后钞箱才变为在途离行。
- **领取互斥**:两名员工同时领取同一钞箱,通过数据库条件更新保证**仅一人成功**。
- **差额六类**:短款、长款、残钞、封签破损、ATM 离线、重复回传,各自带处理期限。
- **补传队列**:进程内串行任务队列 + 指数退避,任务落库;ATM 离线时回传暂存,恢复在线自动补传;按**幂等键判重**,重复回传生成差额且不重复建单。
- **网点权限**:仅本网点员工或清算中心(`is_hq`)可操作该网点数据,跨网点返回 `403 BRANCH_FORBIDDEN`。
- **金额安全**:所有金额以整数「分」存储,元/分转换无浮点误差。
- **附件**:清机附件以原始字节保存到本地目录,数据库仅存元数据,下载字节一致。

## 技术结构

```
src/
  schema.js      SQLite 表结构(版本化迁移)
  db.js          连接、迁移、元/分换算、单号生成
  services.js    业务服务层(所有不变量,与 HTTP 解耦,可直接被测试调用)
  queue.js       进程内任务队列:离线暂存 / 上线补传 / 幂等判重 / 退避重试
  attachments.js 清机附件本地落盘(原始字节、防目录穿越)
  seed.js        演示样例数据
  server.js      零依赖 HTTP:JSON API + 原始字节上传 + 静态资源
public/          零依赖原生单页应用(index.html / styles.css / app.js)
test/            node:test 集成测试(服务层 17 项 + HTTP 端到端 6 项)
```

- 后端:Node.js 22 内置 `node:sqlite` 与 `node:http`,**无第三方依赖**。
- 前端:原生 HTML/CSS/JS,银灰 + 墨绿 + 少量金色;ATM/钞箱分组卡片、券别金额右对齐数字列、
  封签连续轨迹时间线、差额金额与期限双高亮。
- 操作人通过请求头 `X-Employee-Id` 传入(界面顶部选择器自动附带)。

## 主要 HTTP 接口(摘选)

`GET /api/atms`、`POST /api/plans`、`POST /api/plans/:id/lock|execute`、
`POST /api/orders`、`POST /api/orders/:id/entries|review|close|adjust`、
`POST /api/cassettes/:id/seal|unseal|claim|notes`、`POST /api/handovers/:id/signoff`、
`POST /api/discrepancies/:id/resolve`、`POST /api/reports`(入补传队列)、
`POST /api/tasks/drain`(立即补传)、`GET /api/audit`、
`POST /api/orders/:id/attachments`(原始字节)。

> 本系统仅用于业务流程演示与教学,所有账户、卡号、金额均为虚构数据,不接入任何真实金融系统。
